# 09 外部接口契约

## 目标

外部接口用于连接 Open WebUI、管理后台和系统运维。本文档只定义能力和语义，不绑定具体技术协议、路径、编程语言或 SDK。

## 外部接口分组

<!-- markdownlint-disable MD013 -->
| 接口组 | 使用方 | 目的 |
| --- | --- | --- |
| 模型发现接口 | Open WebUI | 发现可用模型 |
| 聊天请求接口 | Open WebUI | 发送用户问题并接收回答 |
| Responses 接口 | HTTP 客户端、端侧、Open WebUI bridge | 创建、流式、后台执行、查询、取消和回放回答 |
| 原生 Run 接口 | 内部系统、scheduler、管理台、受控后端客户端 | 创建、查询、订阅、取消和审批一个执行对象 |
| Realtime WebSocket 接口 | Android / iOS / Desktop / Web 端侧 | 连续文字会话、ASR 文本提交、打断、取消和恢复 |
| 健康检查接口 | 运维系统 | 判断 Gateway 是否可用 |
| 追踪查询接口 | 管理员 | 查询请求链路和审校状态 |
| 证据包查询接口 | 管理员或审核人员 | 查看回答依赖证据 |
| 配置查看接口 | 管理员 | 查看策略状态，不暴露密钥 |
| 评测触发接口 | 测试或治理人员 | 运行标准问题集验证 |
<!-- markdownlint-enable MD013 -->

## 模型发现接口

### 目的

让 Open WebUI 只发现一个可见模型：

> 通灵玉

### 输入语义

1. 调用方身份；
2. 可选的租户或用户组上下文。

### 输出语义

1. 可见模型标识；
2. 模型显示名称；
3. 模型说明；
4. 是否可用；
5. 不返回内部 Agent 列表。

### 验收标准

1. 普通用户只能看到一个模型；
2. 不出现 `honglou-main`、`honglou-text`、`honglou-commentary`、`honglou-reviewer`；
3. 未授权调用者不能发现模型。

## 聊天请求接口

### 目的

接收用户问题，返回最终回答。

### 输入语义

1. 可见模型标识；
2. 用户消息；
3. 会话标识；
4. 调用方身份；
5. 可选的流式或非流式偏好；
6. 不接受用户指定内部 Agent；
7. 不接受用户关闭审校。

### 输出语义

1. 最终回答；
2. 回答状态；
3. 可选的证据链编号；
4. 可选的简要来源说明；
5. 错误或降级说明。

### 验收标准

1. 请求能进入 Gateway；
2. Gateway 能映射到内部流程；
3. 最终回答来自审校后结果；
4. 错误时不泄露内部配置；
5. 用户不能通过输入控制内部工具权限。

## Responses 接口

### 目的

提供 Gateway 新主接口，覆盖同步回答、流式输出、后台长任务、状态查询、取消和
事件回放。该接口是 `/v1/chat/completions` 和 `/v1/realtime/ws` 的共同执行底座。

### 推荐路径

```text
POST /v1/responses
GET /v1/responses/{response_id}
GET /v1/responses/{response_id}/events
POST /v1/responses/{response_id}/cancel
```

### 输入语义

1. 可见模型标识，第一版只允许 `tonglingyu`；
2. 用户输入文本；
3. 会话标识；
4. 幂等键；
5. `stream` 偏好；
6. `background` 偏好；
7. 调用方身份；
8. 不接受内部 profile、tool policy、reviewer、context 或 memory 控制字段；
9. 不接受音频或媒体 payload；
10. `metadata.tenant_id`、`metadata.thread_id` 只能作为客户端关联信息，不能作为鉴权或
    租户归属事实源；
11. `callback_url` 只有在租户级 allowlist、签名 policy 或服务端配置通过后才允许用于
    background completion 通知。

### 输出语义

1. response 编号；
2. response 状态；
3. 公开输出文本；
4. 可选 evidence package 编号；
5. SSE event stream；
6. 脱敏错误码；
7. 取消或失败状态。

### 验收标准

1. `background=true` 能立即返回 queued response；
2. `stream=true` 能从统一 response event stream 输出 SSE；
3. 状态查询能返回 queued、in_progress、retrieving、reviewing、completed、failed
   或 canceled；
4. 取消请求能写入 cancel state，并在 worker 安全点生效；
5. 断线后能按 event id replay；
6. 普通用户不能查询他人 response；
7. 公开响应不泄露 trace、context、memory、tool policy 或 reviewer 内部对象；
8. background callback 失败不会改变 response 终态，只产生可审计的通知失败事件。

## 原生 Run 接口

### 目的

提供 Gateway 原生控制面。Run 是 canonical 执行模型；`/v1/responses`、
`/v1/chat/completions` 和 WebSocket 都是它的协议投影。该接口面向内部系统、
scheduler、管理台和受控后端客户端，Open WebUI 和普通 OpenAI-compatible 客户端
不应优先使用它。Run API 与 `/v1/responses` 必须共用同一执行对象、事件流、
状态机、权限投影和 worker 队列。

### 推荐路径

```text
POST /v1/runs
GET /v1/runs/{run_id}
GET /v1/runs/{run_id}/events
POST /v1/runs/{run_id}/cancel
POST /v1/runs/{run_id}/actions/{action_id}
GET /ws/runs/{run_id}
GET /ws
```

### 输入语义

1. 可见模型或受控 graph/profile 别名；
2. 输入文本、messages 或受控 task payload；
3. 调用方 subject；
4. 真实 tenant、user 和权限上下文，必须来自鉴权结果而不是 metadata；
5. 幂等键；
6. `stream`、`background`、`priority`、`timeout` 等执行偏好；
7. action 提交中的审批决定、人工补充输入或外部工具结果；
8. 不接受用户直接指定 Runtime Adapter、内部 profile、tool policy digest 或 reviewer
   跳过字段。

### 输出语义

1. `run_id`；
2. 对应的 `response_id` 或 `chat_completion_id` 投影；
3. 当前 status；
4. 公开 summary；
5. usage；
6. 脱敏 error；
7. `result_ref` 或 evidence package ref；
8. events URL；
9. `requires_action` 状态和 action 列表。

### 状态语义

Run 状态至少包含：

```text
queued
in_progress
retrieving
composing
reviewing
requires_action
canceling
completed
failed
canceled
timeout
expired
```

`completed`、`failed`、`canceled`、`timeout` 和 `expired` 是终态。终态不能回退，
action 不能提交到终态 run。

### 事件语义

`GET /v1/runs/{run_id}/events` 返回 SSE。必须支持：

1. `Last-Event-ID` 或 `after` 参数断线恢复；
2. 只返回 `visibility=public` 的事件；
3. response 已完成时 replay 历史事件后结束；
4. Redis stream 被 trim 时，可从持久化 event/journal 补关键事件；
5. 客户端按 sequence 去重和排序。

### Action 语义

`POST /v1/runs/{run_id}/actions/{action_id}` 用于 human-in-the-loop 和外部工具回调：

1. action 必须已由服务端创建并分配给当前 subject 或 tenant admin；
2. action 有过期时间、幂等键和状态；
3. 重复提交返回已有 action 结果；
4. 无效、过期、已完成或不属于当前调用者的 action 返回 `403`、`404` 或 `409`；
5. action 只能让 worker 从安全恢复点继续执行，不能直接修改 final answer 或绕过
   reviewer。

### WebSocket 语义

`/ws/runs/{run_id}` 是单 run 双向订阅；`/ws` 可在一个连接中订阅多个 run。二者都必须：

1. 复用 Run owner/tenant admin 权限；
2. 限制单连接订阅数量；
3. 支持 subscribe、unsubscribe、cancel、submit_action 和 heartbeat；
4. 只投影同一 public RunEvent；
5. 不接受音频、二进制帧或内部控制字段。

### 验收标准

1. `/v1/runs` 创建的 run 能被 `/v1/responses/{id}` 或 OpenAI-compatible 投影引用；
2. Run API 和 Responses API 查询同一执行对象时状态一致；
3. cancel 只写 control/cancel 事件，worker 在安全点终止；
4. action submit 有幂等、权限、过期和审计；
5. SSE 和 WS replay 语义一致；
6. 普通用户无法通过 Run API 获得 trace、context、memory、tool policy 或 reviewer
   内部对象；
7. 如果 Run/Response 映射缺失或冲突，必须返回 typed error，不能临时创建第二个 workflow。

## Realtime WebSocket 接口

### 目的

支持端侧连续会话和语音交互场景中的文字事件同步。Gateway 不处理音频；端侧必须
先完成 ASR、VAD、TTS 和播放打断。

### 推荐路径

```text
GET /v1/realtime/ws
```

### 输入语义

1. `session.start` 初始化或恢复会话；
2. `input_text.delta` 提交 ASR 中间文字；
3. `input_text.commit` 提交最终文字；
4. `response.create` 创建回答；
5. `response.cancel` 取消回答；
6. `response.resume` 从指定 event id 后恢复；
7. `ping` 保活；
8. 不接受 binary frame、`input_audio.*`、`output_audio.*` 或媒体字段。

### 输出语义

1. `session.started`；
2. `response.created`；
3. `response.status`；
4. `evidence.found`；
5. `output_text.delta`；
6. `response.completed`；
7. `response.failed`；
8. `response.canceled`；
9. `error`。

### 验收标准

1. WebSocket handshake 必须鉴权和限流；
2. `input_text.delta` 不创建 RQA workflow；
3. `input_text.commit + response.create` 创建 response job；
4. server event 必须来自 Redis response event stream；
5. 断线重连可用 `response.resume` 继续；
6. `response.cancel` 能中断未完成回答；
7. binary/audio payload 被拒绝；
8. 公开 WS event 不泄露内部字段。

## 健康检查接口

### 目的

判断系统是否可以接受请求。

### 输出语义

1. Gateway 状态；
2. Agent Runtime provider/profile 配置状态；
3. 证据检索服务状态；
4. 审校能力状态；
5. 最近错误摘要。

### 验收标准

1. 能区分 Gateway 自身故障和下游故障；
2. 下游故障时可触发降级；
3. 不泄露内部密钥或详细栈信息。

## 追踪查询接口

### 目的

让管理员查询某次回答的内部处理链路。

### 输入语义

1. 追踪编号；
2. 管理员身份；
3. 查询范围。

### 输出语义

1. 请求状态；
2. Agent 调用顺序；
3. 每步状态；
4. 审校结果；
5. 错误类别；
6. 不暴露系统提示词和密钥。

## 证据包查询接口

### 目的

查看某次回答依赖的证据卡片和结论声明。

### 输入语义

1. 证据包编号；
2. 管理员或审核人员身份；
3. 查询原因。

### 输出语义

1. 证据卡片列表；
2. 证据来源；
3. 支持范围；
4. 不支持范围；
5. 结论声明；
6. 证据等级；
7. 审校状态。

## 评测触发接口

### 目的

运行标准问题集，验证检索、回答和审校质量。

### 输入语义

1. 评测集名称；
2. 评测范围；
3. 触发人；
4. 评测版本。

### 输出语义

1. 评测结果摘要；
2. 失败问题列表；
3. 指标变化；
4. 是否达到上线门槛。

## 外部接口负面要求

外部接口不得：

1. 暴露内部 Agent；
2. 暴露工具白名单；
3. 暴露系统提示词；
4. 允许用户关闭审校；
5. 允许用户指定内部 profile；
6. 返回内部异常栈；
7. 返回未脱敏的审计日志；
8. 接收或返回音频媒体流；
9. 让 WS 客户端直接指定内部 Runtime profile 或 tool policy。

## 证据链展示边界

面向 Open WebUI 的聊天接口默认只返回最终回答，不暴露内部 Agent 细节。受控情况下可以返回或展示：

1. 证据包编号；
2. 简要来源说明；
3. 是否涉及脂批；
4. 是否涉及版本差异；
5. 是否存在证据不足提示。

管理员或审核人员查询证据包时，应能查看正文证据、脂批证据、版本证据、人物事件证据、字形读音标注，以及每条证据的支持范围、不支持范围和 reviewer 判断。

普通用户不应通过外部接口直接访问内部检索库或原始未审校证据。
